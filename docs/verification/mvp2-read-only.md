New Home Assistant coverage includes explicit backend configuration, light allowlists, all read states, missing entities, malformed/mismatched payloads, auth/transport failures, timeouts and no automatic retries. API tests exercise read-only composition and recovery. A local HTTP fixture exercises native fetch with bearer authentication and verifies that only a GET to the allowed state endpoint occurs, including after a refused write request. The real Strands fixture confirms that read-only mode registers list_devices only. No real Home Assistant instance, provider charges or physical device operations were used.

The PWA now has a validated device panel, snapshots and refresh/error handling. Production build/assets pass; browser runtime discovery found no connected browser, so visual interaction, offline behavior and installability have not been verified. Live Home Assistant/Pi checks require actual deployment details and remain open. Physical writes, direct controls and LAN authentication/TLS are not delivered in this slice.
